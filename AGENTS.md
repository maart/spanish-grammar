# Spanish Grammar — инструкции для агента

Это автономный русскоязычный справочник и интерактивный учебник по европейскому испанскому. Репозиторий: `https://github.com/maart/spanish-grammar`; основная ветка — `main`, remote `origin`.

## Структура и среда

- `spanish-grammar.html` — единственный основной артефакт: внутри него находятся разметка, CSS, данные и JavaScript.
- `validate-conjugations.js` — dev-скрипт проверки; `README.md` — инструкции запуска; лицензия MIT.
- Не найдено `package.json`, lockfile, Makefile, CI-конфигурации или runtime-зависимостей. Сборщика и отдельного линтера нет.
- Спряжения и лексика соответствуют Испании: используются `tú`/`usted` и `vosotros`, voseo не используется; правила сверяются с RAE.

## Команды

Запускать из корня репозитория:

```bash
node validate-conjugations.js
open spanish-grammar.html
python3 -m http.server 8001
```

После локального сервера открывать `http://localhost:8001/spanish-grammar.html`. Валидатор должен завершаться строкой `RESULT: PASS`; он проверяет данные спряжений, переводы, поиск, квиз, учебный план и примеры времён.

## Правила изменений

- Сохраняй проект однофайловым: не выноси CSS, JS или данные из `spanish-grammar.html`, не добавляй сборщик или dependency.
- При каждом изменении `spanish-grammar.html` обновляй дату и время в футере (`обновлено:`) по Мадриду (CET/CEST).
- При каждом коммите, который меняет HTML, обновляй версию MVP в футере.
- После каждого изменения выполняй `git add`, `git commit` и `git push` в GitHub. Не добавляй в коммит посторонние файлы.
- Связи между разделами: `TENSE_LESSONS` (время → уроки; первый урок задаёт уровень времени), `VERB_LESSONS` (глагол → уроки) и поле `lessons` у шпаргалок в `USEFUL_TABLES` (из него же строятся «Шпаргалки по теме» в уроке и диапазон уровней шпаргалки). У шпаргалок постоянный `id` (адрес `#table-<id>`) и собственный `level`; `validateData()` проверяет все связи.
- Вкладка «План обучения»: уровни A1–B2 строятся из `LEARNING_MODULES` (уроки учебника, шпаргалки, задание, «Могу»), C1–C2 — одна страница «C1 и C2» (`LEARNING_AFTER_B2`, id `after`). Уровня A0 нет ни в Плане, ни у шпаргалок (убран в MVP 1.52; старые отметки переносит `renameRetiredPlanKeys`). Уровни уроков — `TEXTBOOK_LESSON_LEVELS` по PCIC (в книге их нет). `validateData()` требует, чтобы каждый урок уровня с модулями входил ровно в один модуль того же уровня; ссылки должны вести только на точные учебные или проверочные материалы.

## Устройство скрипта

- В начале `<script>` — оглавление; разделы отмечены строками `// ═══════ N. …`. Новый код клади в раздел своей вкладки, данные — в разделы данных.
- HTML собирай шаблоном `` html`…` ``: он сам экранирует подстановки; готовую разметку передавай через `rawHtml(...)`. Ручные `escapeHTML` + конкатенация остаются только в старом коде.
- Обработчики событий регистрируй через `onDelegated(type, selector, handler)` с селектором, привязанным к контейнеру вкладки (`.learning-plan …`, `inTextbook(…)`), а не навешивай после каждой отрисовки. Остальные вкладки пока на `bindClickAll` — переводить постепенно.
- Поля `state` сохраняй через `persist("имяПоля")` (ключ `msg:имяПоля`); читать — `readStoredObject` / `readStoredArray`.
- После перерисовки возвращай фокус через `rerenderAndFocus(render, selector, { keepScroll })`.
- Урок по номеру — `lessonById(id)`, уровень урока — `textbookLessonLevel(id)`, подписи уровней — `levelLabel` / `levelRangeLabel`.

## Питфоллы

- Валидатор извлекает первый `<script>` из HTML и ожидает маркер `const dataIssues = validateData();`; не перемещай его без одновременного обновления валидатора.
- Данные и прогресс приложения сохраняются в `localStorage`; не рассчитывай на состояние браузера при проверке.
- В рабочем дереве может быть незатреканный `Gramatica_de_Uso_A1-B2.pdf`; не добавляй его автоматически.
- Номер страницы PDF и напечатанный номер страницы учебника могут различаться; после `pdftoppm` сверяй цифру внизу изображения перед переносом материала.
- `node validate-conjugations.js` запускает и встроенную `validateData()`: она проверяет структуру `TEXTBOOK_LESSONS` (переводы, feedback, дополнительные блоки теории, уникальные ID, наличие ответа среди вариантов). Правильность самих ответов упражнений и соответствие материала учебнику по-прежнему проверяй вручную.
- В упражнениях с местоимениями проверяй точку зрения говорящего: `te` может стать `me`, а `os` — `nos`; не переноси ключи только по внешнему шаблону предложения.
- Если исходное упражнение содержит несколько пропусков, адаптируй его под одно поле ответа и явно укажи в условии, какая часть уже заполнена; после UI-теста очищай тестовый прогресс и останавливай локальный сервер.
